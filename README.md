# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

В приложении используются следующие интерфейсы для типизации данных, получаемых от сервера и вводимых пользователем:

### `IProduct`
```typescript
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```
**Назначение:** Описывает сущность товара. Используется для получения данных с сервера, отображения карточек в каталоге, детального просмотра и формирования состава заказа.

### `IBuyer`
```typescript
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```
**Назначение:** Описывает данные покупателя, необходимые для оформления заказа. Включает выбранный способ оплаты и контактные данные для доставки.

## Модели данных

Классы, отвечающие за хранение, управление и валидацию данных. Каждый класс изолирован и выполняет строго одну задачу.

### `CatalogModel` (Каталог товаров)
**Назначение:** Хранит массив всех доступных товаров и управляет состоянием товара, выбранного пользователем для детального отображения.  
**Конструктор:** Не принимает параметров. Инициализирует внутренние поля пустыми значениями.  
**Поля:**
- `_items: IProduct[]` — массив всех товаров, загруженных с сервера.
- `_selectedProduct: IProduct | null` — ссылка на товар, выбранный для просмотра в модальном окне.

**Методы:**
- `setItems(items: IProduct[]): void` — сохраняет переданный массив товаров в модель.
- `getItems(): IProduct[]` — возвращает массив всех доступных товаров.
- `getItemById(id: string): IProduct | undefined` — возвращает объект товара по его уникальному идентификатору.
- `setSelectedProduct(product: IProduct): void` — сохраняет переданный товар как текущий выбранный для детального отображения.
- `getSelectedProduct(): IProduct | null` — возвращает ссылку на текущий выбранный товар.

### `BasketModel` (Корзина)
**Назначение:** Хранит массив товаров, добавленных пользователем для покупки. Отвечает за управление составом корзины и расчёт итоговых значений.  
**Конструктор:** Не принимает параметров. Инициализирует пустой массив товаров.  
**Поля:**
- `_items: IProduct[]` — массив товаров, находящихся в корзине на данный момент.

**Методы:**
- `getItems(): IProduct[]` — возвращает массив товаров в корзине.
- `addItem(product: IProduct): void` — добавляет переданный товар в массив корзины.
- `removeItem(id: string): void` — удаляет товар из корзины по его идентификатору.
- `clear(): void` — полностью очищает массив товаров в корзине.
- `getTotalPrice(): number` — возвращает суммарную стоимость всех товаров в корзине.
- `getTotalItems(): number` — возвращает общее количество товаров в корзине.
- `hasItem(id: string): boolean` — проверяет наличие товара с указанным идентификатором в корзине, возвращает `true` или `false`.

### `CustomerModel` (Покупатель)
**Назначение:** Хранит контактные данные покупателя и способ оплаты, выбранные при оформлении заказа. Обеспечивает поочерёдное обновление полей без сброса остальных данных и валидацию введённой информации.  
**Конструктор:** Не принимает параметров. Инициализирует поля значениями по умолчанию.  
**Поля:**
- `payment: TPayment | null` — выбранный способ оплаты.
- `email: string` — адрес электронной почты.
- `phone: string` — номер телефона.
- `address: string` — адрес доставки.

**Методы:**
- `setPayment(payment: TPayment): void` — сохраняет выбранный способ оплаты.
- `setEmail(email: string): void` — сохраняет адрес электронной почты.
- `setPhone(phone: string): void` — сохраняет номер телефона.
- `setAddress(address: string): void` — сохраняет адрес доставки.  
*(Каждый сеттер обновляет только своё поле, не затрагивая значения остальных полей)*
- `getOrderData(): IBuyer` — возвращает объект со всеми текущими данными покупателя, приведённый к типу `IBuyer`.
- `clear(): void` — сбрасывает все поля покупателя к значениям по умолчанию.
- `validate(): Record<string, string>` — проверяет заполненность полей. Возвращает объект, где ключами являются имена полей с ошибками, а значениями — текст ошибки. Если поле валидно, оно отсутствует в возвращаемом объекте.  
  Пример возвращаемого объекта при наличии ошибок:
  ```typescript
  {
    payment: 'Не выбран вид оплаты',
    email: 'Укажите емэйл'
  }
  ```
## Слой коммуникации

Класс `WebLarekAPI` отвечает за взаимодействие с сервером приложения. Использует паттерн композиции: принимает в конструктор экземпляр базового класса `Api` и использует его методы `get` и `post` для отправки запросов.

### `WebLarekAPI`
**Назначение:** Получение списка товаров и отправка данных заказа на сервер.
**Конструктор:**
- `constructor(api: IApi)` — принимает экземпляр базового API-класса.

**Методы:**
- `getProducts(): Promise<IProduct[]>` — делает GET-запрос к эндпоинту `/products`. Возвращает массив товаров.
- `createOrder(order: IOrderData): Promise<IOrderResult>` — делает POST-запрос к эндпоинту `/order`. Принимает объект с данными заказа, возвращает объект с результатом (id заказа и общая сумма).

## Слой представления (View)

Классы, отвечающие за отрисовку интерфейса и перехват пользовательских событий. Не содержат бизнес-логики и общаются с остальным приложением через события.

### Иерархия наследования карточек
Так как HTML-шаблоны для карточки в каталоге и карточки в корзине отличаются, реализована двухуровневая структура:
1. **`BaseCard`** — минимальная карточка (заголовок, цена).
2. **`FullCard`** (наследует `BaseCard`) — полная карточка (добавляет картинку, описание, категорию).

### `Component<T>` (Базовый UI-компонент)
**Назначение:** Фундамент для всех визуальных элементов. Управляет корневым DOM-элементом и подпиской на события.
**Наследование:** Абстрактный класс.
**Конструктор:** `constructor(container: HTMLElement, events?: IEvents)`
**Поля:**
- `container: HTMLElement` — корневой DOM-элемент компонента.
- `events?: IEvents` — брокер событий.
**Методы:**
- `render(data?: Partial<T>): HTMLElement` — возвращает корневой DOM-элемент. В дочерних классах заполняет DOM данными.
- `getContainer(): HTMLElement` — публичный геттер для доступа к контейнеру.
- `setText(element: HTMLElement, value: unknown): void` — устанавливает текстовое содержимое.
- `setImage(element: HTMLImageElement, src: string, alt?: string): void` — обновляет источник и alt изображения.
- `setDisabled(element: HTMLElement, state: boolean): void` — управляет состоянием `disabled`.
- `subscribe(element, event, handler): void` — подписка на DOM-события.
- `emitEvent(event, data): void` — генерация события через брокер.

### Карточки товаров

#### `BaseCard` (Базовая карточка)
**Назначение:** Родитель для карточек, у которых есть только название и цена (используется для корзины).
**Наследование:** `extends Component<IProduct>`
**Методы:**
- `render(data: IProduct): HTMLElement` — заполняет заголовок и цену.

#### `FullCard` (Полная карточка)
**Назначение:** Родитель для карточек с расширенной информацией (каталог, детальное окно).
**Наследование:** `extends BaseCard`
**Поля:**
- `description`, `image`, `category` — ссылки на DOM-элементы (могут быть `null`, если их нет в шаблоне).
**Методы:**
- `render(data: IProduct): HTMLElement` — вызывает рендер родителя, затем заполняет описание, картинку и категорию.

#### `CardPreview` (Карточка в каталоге)
**Назначение:** Отображает товар в общей сетке на главной странице.
**Наследование:** `extends FullCard`
**Методы:**
- `render(data: IProduct & { inBasket: boolean }): HTMLElement` — рендерит карточку и настраивает кнопку ("Купить" / "Удалить").
**События:**
- `preview:buy` — клик по кнопке действия в каталоге.

#### `CardFull` (Детальная карточка)
**Назначение:** Отображает товар в модальном окне при клике на карточку из каталога.
**Наследование:** `extends FullCard`
**Методы:**
- `render(data: IProduct & { inBasket: boolean }): HTMLElement` — рендерит полную карточку в модалке.
**События:**
- `full:buy` — клик по кнопке действия в модальном окне.

#### `CardBasket` (Товар в корзине)
**Назначение:** Элемент списка в модальном окне корзины. Содержит только заголовок, цену и кнопку удаления.
**Наследование:** `extends BaseCard`
**Методы:**
- `render(data: IProduct): HTMLElement` — рендерит элемент списка.
**События:**
- `basket:remove` — клик по кнопке удаления товара.

### Формы

#### `Form` (Базовая форма)
**Назначение:** Логика работы с полями ввода, заполнением и валидацией.
**Наследование:** `extends Component<IBuyer>`
**Методы:**
- `render(data: Partial<IBuyer>): HTMLElement` — заполняет поля `input` значениями из объекта данных.
- `valid(errors: Record<string, string>): boolean` — принимает объект ошибок. Если есть ошибки — блокирует кнопку submit и выводит текст ошибки. Если ошибок нет — разблокирует кнопку.
**События:**
- Генерирует события вида `order:change` или `contacts:change` при вводе данных в поля.

#### `OrderForm` (Форма 1: Оплата и Адрес)
**Назначение:** Первый шаг оформления заказа.
**Наследование:** `extends Form`
**События:**
- `order:submit` — нажатие кнопки "Далее".

#### `ContactsForm` (Форма 2: Контакты)
**Назначение:** Второй шаг оформления заказа.
**Наследование:** `extends Form`
**События:**
- `contacts:submit` — нажатие кнопки "Оплатить".

---

### `Modal` (Модальное окно)
**Назначение:** Универсальный контейнер для отображения контента поверх страницы.
**Наследование:** `extends Component`
**Методы:**
- `open(): void` — добавляет класс активности, блокирует скролл body.
- `close(): void` — скрывает окно, возвращает скролл.
- `render(content: HTMLElement): HTMLElement` — очищает содержимое модалки и вставляет туда переданный элемент.

### `Page` (Главная страница)
**Назначение:** Управляет общей разметкой страницы.
**Наследование:** `extends Component`
**Методы:**
- `setCatalog(items: HTMLElement[]): void` — отрисовывает сетку товаров.
- `setCounter(count: number): void` — обновляет счетчик корзины.
**События:**
- `page:basket` — клик по иконке корзины в хедере.

## Презентер

Презентер — это слой приложения, который отвечает за бизнес-логику и координацию между Моделями и Представлениями. В данном проекте Презентер реализован в файле `main.ts`.

### Принцип работы
Презентер подписывается на события от Моделей и Представлений с помощью брокера событий (`EventEmitter`).
1. Запрашивает или изменяет данные в **Моделях**.
2. Вызывает методы рендеринга **Представлений**.
3. Управляет открытием/закрытием модальных окон.

### Обработанные события

#### События от Моделей данных (обновление интерфейса):
- `catalog:changed` — каталог товаров обновлён. Презентер перерисовывает сетку товаров на главной странице.
- `product:selected` — товар выбран для детального просмотра. Презентер открывает модальное окно с полной карточкой товара.
- `basket:change` — содержимое корзины изменилось. Презентер обновляет счётчик на иконке корзины и перерисовывает содержимое корзины.
- `customer:change` — данные покупателя изменились. Презентер проверяет валидность формы и активирует/деактивирует кнопку отправки.

#### События от Представлений (действия пользователя):
- `page:basket` — клик по иконке корзины в хедере. Презентер открывает модальное окно корзины.
- `preview:buy` / `full:buy` — клик по кнопке «Купить». Презентер добавляет товар в корзину или удаляет его, если он уже есть.
- `basket:remove` — клик по кнопке удаления товара из корзины. Презентер удаляет товар и обновляет корзину.
- `modal:close` — закрытие модального окна. Презентер скрывает окно.
- `order:change` / `contacts:change` — изменение полей формы. Презентер обновляет данные в Модели покупателя и проверяет валидность.
- `order:submit` — переход ко второму шагу оформления. Презентер переключает формы в модальном окне.
- `contacts:submit` — завершение оформления заказа. Презентер отправляет данные на сервер, очищает корзину и показывает успех.

### Архитектурные решения
- Презентер не генерирует события, только обрабатывает их.
- Презентер не хранит данные, только работает с Моделями.
- Презентер не знает о структуре DOM, только работает с Представлениями.
- Все зависимости внедряются через конструкторы (инверсия зависимостей).
